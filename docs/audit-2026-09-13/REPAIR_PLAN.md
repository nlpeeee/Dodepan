# Ordered repair batches

These are implementation specifications resulting from the audit, not changes already made to production firmware. Keep each batch reviewable against the recorded working-copy baseline. Do not combine an upstream update with audio or data-layout repairs.

## 1. Audio transport correctness and diagnostics — A01, A04, A05

- Introduce explicit buffer states (`FREE`, `RENDERING`, `READY`, `PLAYING`) and monotonically increasing handoff generations. A producer may write only a claimed free buffer; DMA may consume only a completed published buffer. Use a fixed pool of three 128-frame buffers plus an immutable silence buffer. Hardware-rearm timing must be measured; use chained DMA to avoid making every handoff depend on a lowest-priority IRQ. Underrun must select the silence buffer and increment a counter, never replay or consume partially written memory.
- Replace the pointer-poll interface with `audio_acquire_buffer`, `audio_publish_buffer`, `audio_start`, `audio_request_stop`, and `audio_get_diagnostics`. Use fixed-size storage and fail startup visibly if hardware resources cannot be claimed. Prefill before starting DMA/PIO. Ownership publication needs SDK-supported synchronization/memory ordering; `volatile` alone is insufficient.
- Derive the PIO divider from the assembled program's 64 cycles/frame and `clock_get_hz(clk_sys)`. Check clock-setting success and verify the resulting BCLK/LRCLK. Keep a labeled 24 kHz baseline for comparison, but the repaired nominal path must produce 48 kHz. Preserve the 16-bit duplicated-left format for this batch.
- Keep 288 MHz only as an experimental comparison point. Benchmark at 150, 192, 240, and 288 MHz with otherwise identical settings; select the lowest clock meeting the measured workload and hardware stability criteria. A larger buffer is not a cure for insufficient average processing capacity.
- Publish a coherent `audio_diagnostics_t`: actual system/frame clocks, frame count, DMA completions, underruns, late publications, maximum render time, maximum handoff/IRQ gap, event queue high-water/overflow, and main-loop maximum delay. Define render-time and deadline checks in microseconds against actual frame rate. Keep counters single-writer; publish a consistent snapshot once per second, with no printf, allocation, or I2C in the renderer/IRQ.
- Provide compile-time diagnostic switches for display activity, IMU polling, persistence, stereo frame count, and system clock; all settings and source/engine hashes must appear in the diagnostic startup identity. Keep USB MIDI identity stable. Use the existing UART output for optional machine-readable diagnostics; budget or drop log lines rather than blocking the render owner.

Acceptance: structural frame-rate check passes; hardware confirms 48 kHz LRCLK and 1.536 MHz BCLK; forced late-render tests produce a counted fallback, never an ownership violation. Four-voice/effects stress at the selected clock has zero underruns/late publications, with worst-case render time no more than 80% of the 2.667 ms nominal buffer period. Confirm the added buffering's latency by measurement.

## 2. Synth ownership and safe persistence — A02, A03, F01, F08, F09

- Make core 1 the exclusive owner of all synth methods after startup. Core 0 submits ordered note, controller, pitch, preset-apply, and panic commands through a bounded 256-entry queue. Represent a preset change as one fixed-size transaction containing its complete controller values. Never allow flash or the UI to inspect mutable synth internals directly; publish a controller mirror only after applying a complete transaction.
- Drain a bounded amount of queued work at each audio-block boundary and preserve event ordering. Coalesce redundant continuous controls before enqueueing when no intervening note/preset event depends on them. On saturation, count the failure and request an out-of-band panic/resynchronization; do not silently lose note-off events. Mark an overflowing diagnostic run failed.
- Fix all user-instrument mappings together: IDs 0–5 custom, 6–13 existing engine programs, 14–17 user slots 0–3. Share the mapping with menu limits and saving; reject any invalid slot before indexing.
- Add explicit legacy and new persistence readers. Legacy is the current `DODE` 244-byte layout: 16-byte prefix, four 45-byte presets, then four 12-byte scales. Preserve its four stored slots byte-for-byte by slot position. Do not infer an old user's intended slot from buggy instrument IDs. Retain a recognized selected instrument ID and document the corrected mapping.
- New storage uses a versioned, length-checked, CRC-protected record and a generation number. Reserve two dedicated 4 KiB sectors through the linker rather than assuming the current 2 MiB offset is permanently unused. For Pico 2's 4 MiB layout use the last two sectors, leave the legacy sector readable for migration, and add build-time overlap checks. Write and verify the inactive record before adopting its generation; choose the newest valid record at startup. Preserve legacy data until a valid new record exists.
- Store all 48 parameters with `size_t` offsets. Validate controller values against their supported ranges and scale degrees against the existing 0–24 scale-editor range before mutating runtime state. Supply deterministic engine defaults for the three fields absent from legacy records and list them in migration notes. Reject corrupt records as a unit and use safe defaults if neither new nor legacy data is valid.
- Replace the alarm's flash operation with a flag. A main-loop save state machine waits until all playback sources are stopped, no pads are held, and the audio tail has stayed below a defined quiet threshold (absolute sample <=32 for 250 ms). Continuous drones keep the save pending. Then request renderer acknowledgement, ramp to zero, stop DMA/PIO, perform the flash transaction with the SDK's supported multicore/XIP coordination, prefill, restart, and clear dirty flags only after verified success. Display a pending-save indicator using existing UI space; do not claim unsaved changes survived a power-off.

Acceptance: slot mapping and complete-parameter tests pass; all four distinct presets/scales survive legacy migration and reboot. Add CRC, invalid range, bad length, erased record, interrupted-write, and newest-valid-generation tests. Stress queue saturation and rapid preset changes; no partially applied patch or unmatched note event is allowed. On-device save tests show no uncontrolled click, transport stall, or crash. Electrical power-loss testing and save audio remain hardware gates.

## 3. Existing feature reliability — F02–F07, H01, U01

- Track notes by source: each pad, arpeggiator, looper, and demo. Associate pad release with the source that handled its press. Transport stop/clear releases only its own notes; global panic releases all internal and emitted MIDI notes, clears sustain, and resets all held-pad and tilt state. Retain engine voice stealing for the four-voice limit.
- On arp/chord/instrument/key/scale changes, explicitly release the affected source's old notes and reset its tracking. Require a fresh touch after a mode change rather than silently transferring a held gesture. Other playback sources continue unless the user invokes global panic. Apply preset changes transactionally and document that changing instrument releases current synth voices.
- Tilt transitions construct a root-inclusive target chord and route balanced removed/added notes through the same synth/MIDI/looper path. Keep unchanged pitches held. Remove the current unsupported assumption that a polyphonic note-on automatically morphs a particular voice; smooth voice-specific glide is deferred. Restore temporary portamento settings when leaving tilt mode.
- Looper playback drains due events through each boundary before advancing from the previous cycle epoch, not the latest poll time. On large scheduling gaps, release loop-owned voices and resynchronize to the current cycle; count the missed cycle instead of emitting an unbounded catch-up burst. Pause, clear, restart, and stop close outstanding loop-owned notes.
- Enforce recording duration from `looper_task`, even without new input. Reserve space for releases of outstanding recorded notes; when remaining space is insufficient, close the recording safely and show that the limit was reached. Only positive-velocity note-on can auto-arm IDLE/PAUSED; note-off must not erase a saved loop.
- Use a 64-bit monotonic timebase for musical scheduling. Normalize arp index/octave/direction after range changes; calculate notes in a wide type before MIDI-range checks. Preserve the 80% gate and present pattern choices; define single-note UP_DOWN as a nonduplicating octave bounce.
- Demo scheduling accumulates delta durations using the tempo active during that interval, with remainder preserved. Bound-check each complete event/VLQ and tempo payload; reject zero PPQN/tempo and invalid status. Keep the existing embedded-song feature; no new file-upload parser is added.
- IMU failures retain last valid data temporarily, then use neutral bend/filter/velocity defaults and expose an unavailable sensor state. Use a bounded integer magnitude calculation with a defined zero-input result. Convert touch debounce to elapsed-time behavior and sample all electrode states once per poll; choose the release interval from measured tap/release tests, not CPU loop speed. Accumulate encoder detents with an atomic consume operation.

Acceptance: all relevant baseline failure probes turn green, plus tests for duplicate pitches across sources, sustain, mode changes with held notes, repeated stop/restart, full/empty loop, long scheduling gaps, malformed assets, clock rollover, and missing IMU. Verify internal synth and external MIDI event traces agree. Recheck existing menus and repeat the hardware stress matrix.

## 4. Optional engine migration — gated

Follow [UPSTREAM_ASSESSMENT.md](UPSTREAM_ASSESSMENT.md). Retain the v1.6.0 engine until batches 1–3 and hardware gates are complete. Migration requires a separately built candidate, sound/preset comparison, new memory and timing measurements, and user review of audible changes. No automatic migration or selective DSP backport is recommended by this audit.

## Release record

For each batch retain source hash, UF2 hash, build/toolchain identity, test results, and device measurements. Only call crackling fixed after the original reproduction no longer fails and every tested unit completes the 30-minute protocol. Keep the baseline UF2 and raw settings backup as comparison/rollback artifacts; preserve a recoverable legacy settings copy when introducing a new storage format.
